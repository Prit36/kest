# CUI 1.1 component update

Kest now pins CUI 1.1.0 at `d0383c4d3c00b7769f6b11cefdf581e1800f2da3`.
The dependency URL and content hash are in `build.zig.zon`; no downloaded
source is patched. The new source modules and their dependencies are compiled
by Zig, including the grid/tree table, Markdown and extras used by code blocks.

## User-visible changes

- Native document tabs replace the custom strip. They keep the request method,
  name, dirty marker, tooltip and close confirmation. Dragging or Shift+Left/Right
  on a focused tab reorders documents. The active request follows its tab, and
  order is saved through the existing workspace writer. New tabs and tabs in a
  resized strip are revealed even before CUI has their initial geometry.
- The collection browser uses CUI's tree table, including guides, chevrons,
  keyboard navigation and type-ahead. Existing collection filtering, request
  opening, context menus and row action menus remain available. Its projection
  uses the existing cached rows; expanding a collapsed branch loads its children
  from the in-memory collection model on the following frame.
- A native path bar shows the full collection/folder/request ancestry and
  collapses middle segments when space is tight. Clicking an ancestor clears
  the collection filter, reveals that node and opens the workspace browser.
  The pencil action still renames the current request. Path typing is disabled
  because collection names are not filesystem paths or unique request IDs.
- The native activity console adds level filters, text filtering, Follow, Copy
  and Clear. Only the engine's redacted events enter the bounded UI buffer.
  The source ring retains 256 events; the display has 256 line slots and 256 KiB
  of text capacity. Clear resets both rings; opening the panel after hidden
  activity or a source reset does not replay stale entries.
- `text/markdown` and `text/x-markdown` responses expose a Markdown Preview.
  Formatting includes lists, tables and fenced code. Task clicks never modify
  the response. Only explicitly clicked HTTP/HTTPS links open externally.
  Documents above 256 KiB fall back to the existing virtualized text viewer;
  raw view and full-body export remain available.
- Layout choice and the side-by-side divider ratio now persist in workspace
  preferences. Older workspace files keep their defaults; invalid values fall
  back or are clamped. Existing request, collection and environment formats stay
  compatible.

## Component decisions

The custom large-document editor stays in use. CUI 1.1's editor scans its
NUL-terminated buffer and rebuilds its line index every frame, and a focused
editor schedules caret wakeups. Kest caches the index by document version and
uses a steady caret. The diagnostic self-test now samples the upstream editor
in an isolated context so this decision can be revisited with measurements.
This also avoids replacing the existing bounded undo/search model prematurely.

Docking and response diffing are not enabled. Docking would change the workspace
interaction and layout format; response comparison needs a defined baseline and
response retention behavior. Neither is required to replace the current custom
controls. Timeline, graph and animation editors do not serve the HTTP workflow.

The CUI-internal boundary in `host.c` and `controls.c` was reviewed. The obsolete
custom document-tab painter was removed. A small scroll-reveal helper remains
for the native strip's newly added tabs and resize behavior. Network workers,
export lifetimes, redaction, reduced motion and idle scheduling are unchanged.

## Validation (2026-11-07)

- `zig fmt --check build.zig build.zig.zon src tests` passed.
- `zig build test --summary all` and
  `zig build test -Doptimize=ReleaseFast --summary all` passed. The 88 engine/HTTP
  tests and separate CUI harness cover native-tab overflow/reveal, keyboard
  reordering, dirty-close confirmation, breadcrumb click/filter reset, tree
  keyboard expansion, activity ring wrap/redaction/search/Clear/reopen, real
  loopback Markdown preview and oversized fallback, plus the previous checks.
- A diagnostics build completed `--self-test --snapshot=...` in an explicit
  scratch workspace with exit 0. Desktop, light, compact, sidebar and activity
  scenes are generated by the snapshot suite; desktop, 640x420 and activity
  images were visually inspected. No developer window or clipboard was used.
- The production ReleaseFast build is `zig-out/bin/kest.exe`, 2,570,240 bytes.
  Three private-desktop native runs exited 0; first idle was 151.4 / 129.8 /
  129.8 ms, working set 58.3 / 57.5 / 57.5 MiB, and normalized idle CPU was
  0.000% over three seconds per run. These are short, warm-cache observations.
- The final ReleaseFast headless run measured the cached editor's 4 MiB
  single-line workload at 0.177 ms median and 0.365 ms p99 over 200 frames, with
  settled redraw false and no scheduled wakeup. The isolated upstream editor
  sample measured 1.723 ms median over eight frames. The contexts and sample
  counts differ; these are diagnostic observations, not a controlled ratio.

Real OS clipboard/dialog behavior, native drag gestures, screen readers, IME
and complex scripts still need manual platform testing. The host remains
Windows-only. See [supported features](supported_features.md) for verification
levels and [measurements](performance.md) for workload exclusions.
